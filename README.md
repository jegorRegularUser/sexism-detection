# Нейро-детектор сексизма в вашем сообщении!

ML-проект: бинарный детектор сексизма на DistilBERT с веб-интерфейсом.
Модель отличает враждебность в адрес женщин (сексизм) от общего хейта,
троллинга и нейтрального текста — и объясняет уверенность.

Демо: https://jegorregularuser.github.io/sexism-detection/
API: `POST /predict/` → `{"text": "...", "model": "sexism-distilbert-v2"}`

## Задача

`1` = сексизм (враждебность в адрес женщин), `0` = не сексизм.
Негативный класс включает **не-сексистский хейт** (расизм, атаку на религию
и т.п.) — отделить сексизм от «просто грубости» принципиально сложнее, чем
детектировать любой хейт подряд, и именно это здесь и решается.

## Пайплайн v2

```
ml/prepare_data.py   # публичные датасеты → чистка → баланс → сплиты → аугментация
ml/train.py          # DistilBERT: fp16, взвешенный лосс, ранний стоп по F1, подбор порога
ml/evaluate.py       # тест-сплит + разбивка HateCheck по функциональностям
ml/predict.py        # CLI-инференс
back.py              # FastAPI: перевод RU→EN, ленивая загрузка, вероятности
data/processed/      # train/val/test CSV + dataset_card.md
reports/             # метрики, confusion matrix, кривые обучения, сравнение моделей
```

### Данные (все публичные, сборка воспроизводится одной командой)

- **Measuring Hate Speech** (UC Berkeley, 135k аннотаций → ~39k комментариев) —
  агрегация по `comment_id`: hateful (score ≥ 0.5) + таргет-женщины (≥ 0.5 голосов
  аннотаторов) → `1`; benign (score ≤ −1) → `0`; hateful **без** гендерного таргета →
  `0` (это сложные негативы); противоречивые гендерные таргеты — в мусор.
- **AG News** — 6k нейтральных заголовков (доменное разнообразие негатива).
- **HateCheck** (3 728 функциональных тест-кейса) — выделенный тест, в обучении
  не участвует ни в каком виде.

### Чистка и аномалии (`dataset_card.md` — полная статистика)

HTML-анэскейпинг (в т.ч. двойной), маскирование URL/упоминаний, mojibake и
не-латиница, границы длины, `langdetect=en`, дедупликация, отбрасывание
текстов с противоречивыми метками. Аугментация — только короткие train-тексты
получают обфусцированные копии (leet, перестановка символов, вставка пробелов),
сплит делается **до** аугментации, чтобы копии теста не утекали в train.

### Обучение

class weights (inverse frequency), cosine LR с warmup, fp16 на GPU,
early stopping по F1 (patience 2), лучшая эпоха по val-F1, порог решения
подбирается по валидации и сохраняется в модель (`threshold.json`) —
бэкенд, CLI и оценка используют один и тот же порог.

## Результаты

Held-out тест (3 085 строк, стратифицированный):

| Модель | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| **sexism-distilbert-v2** | **0.947** | **0.741** | 0.799 | **0.769** | **0.969** |
| local_5 (старая лучшая) | 0.917 | 0.535 | **0.826** | 0.649 | 0.935 |

Старые модели ловят больше «чего-то злого», но** путают сексизм с любым хейтом**:
на негативах вида «расизм без женщин» точность 83–87% против 93% у новой,
precision падает до 0.53–0.60. На HateCheck у старых выше recall на шаблонных
фразах (`reports/model_comparison.csv`) — их исходный CSV был ближе к такому
стилю; новый корпус — реальные комментарии Reddit/Twitter.

Разбивка по 29 функциональностям HateCheck: `reports/hatecheck_breakdown.csv`
+ PNG. Слабые места честно видны там же:

- **имплицитный сексизм без слуров** (derog_impl, negate_pos) — в корпусе MHS
  позитивы в основном прямые; лечение — гейтнутые датасеты EDOS/EXIST (SemEval),
  это главный пункт future work;
- **обфускация** («w0m3n») — частично закрыта аугментацией, но многосимвольные
  искажения остаются трудными.

## Как воспроизвести

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Linux/Mac: .venv/bin/pip

python ml/prepare_data.py      # соберёт data/processed/*.csv (~35k строк)
python ml/train.py             # обучит models/sexism-distilbert-v2 (~5 мин на RTX 4070)
python ml/evaluate.py          # метрики теста + HateCheck breakdown
python ml/predict.py "women belong in the kitchen"
uvicorn back:app               # поднять API
```
